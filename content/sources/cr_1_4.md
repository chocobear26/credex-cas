# CR-1.4 – Website und Freigabe-Workflow

Der Change Request für die Website rund um die Dokumentation. Kein Artefakt ändert inhaltlich.

## Anfrage

Angefragt von Cem Öngören am 07.11.2026, als Teil von «S-Tier, keine Kompromisse».

## Analyse

Die Oberfläche von Docsy war englisch, die Landing Page beschrieb noch die Vorlage, es gab keine Druckfassung für das Anhänge-ZIP, und eine Freigabe setzte eine lokale Installation voraus. Ohne Freigaben bleibt jede Seite «von KI geschrieben», das zentrale Signal des Open Knowledge Format.

## Grundlagen

Docsy 0.17 (Sprache, Druckansicht, GitHub-Links), GitHub Actions.

## Entscheide

- Oberfläche auf Deutsch, eigene Farben (Schiefer, Rot für «neu»), kompakte Seitenleiste, Fusszeile der Gruppe.
- Druckansicht `/_print/` für jeden Abschnitt; daraus entsteht die PDF-Fassung für das Anhänge-ZIP.
- Links «Seite bearbeiten» auf GitHub.
- Neuer Workflow **Freigabe erfassen**: Ein Mensch aus der Gruppe wählt Namen und Seiten, der Workflow trägt `verified` ein, erzeugt die Seiten neu und veröffentlicht. Jarvis startet ihn nie.
- Neue erzeugte Seite [Freigaben](../traceability/freigaben.md) mit dem Stand pro Artefakt; `make verify` ruft danach `make generate` auf.
- Landing Page auf Deutsch, mit dem Fall und einem Knopf zur Dokumentation.
